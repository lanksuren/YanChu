# 言出 · 产品定义 v2（草案）

> 一句话：**说话，就地写成书面文字。**

> 本稿在 v1（`产品定义.md`）基础上补齐五节：目标用户与非目标、时序与延迟、保真契约、落点与降级、隐私与数据，并把讨论中定下的六个决定固化成可检验的条款。评审通过后由本稿替换 v1。

---

## 一、它是什么

一个常驻桌面的语音输入工具。按住键说话，松手后，整理好的文字直接出现在你按下键时正在编辑的那个输入框里，中英文混说都行。

和语音输入法的区别：**它交付的是"整理好的文字"，不是"逐字转写"**。你说的是口语，落到屏幕上是书面语——口头语被清掉、标点补齐、语序通顺，但你说的事一点不走样。

**输入框里只出现定稿。** 说话过程中的草稿全部留在气泡里，从不写进文档。

---

## 二、为谁做

**第一批用户**：中英混说的技术/办公人群——开发者、外企员工、科研人员。

他们的共同点：术语和专有名词多，一句话里中英来回切；写出来的东西会被别人看，不能留口语痕迹；输入框散落在 IDE、浏览器、IM、终端里。

他们今天的做法：拼音打字慢；说给输入法，得到一堆口语转写，还得自己再改一遍。

**我们要省掉的，就是"再改一遍"。**

**非目标**（明确不做）：

- 不做会议记录、录音转写——那是长音频处理，不是输入
- 不做翻译
- 不做语音命令（"打开微信"这类）
- 不做实时字幕
- 不为具体应用做适配，不提供应用内插件

---

## 三、核心能力

### 1. 一键说话，说完即得

按住一个键说话，松手出字；也可以按一下开始，再按一下或 Esc 结束。全程不切窗口、不点按钮。
触发键可自定义（组合键 / 单个功能键 / 长按触发），不写死在代码里。

落点 = 开始录音时正在编辑的那个输入框；说话过程中切了窗口，落点不变。
结束时如果落点已经失去焦点，文字进剪贴板并提示按 Ctrl+V 粘贴，不往别处乱插。

**松手就是结束信号。** 按住说话天然带 end-of-utterance，不需要靠静音检测等待"说完了"。
按一下模式则由「再按一次」或 Esc 给出明确的结束信号，两种模式都不依赖猜测。

### 2. 中英混说

一句话里中英文自由切换，不需要事先选语言、不需要手动切模式。

英文术语、人名、产品名、代码词保持原样，不被译成中文谐音。

### 3. 实时预览气泡

说话时，光标附近浮出一个小气泡，边说边显示。

气泡里有两类内容，用视觉区分：**已说完的句子**（小润色后的样子）和**正在识别的半句**（灰字）。

气泡只读：不可编辑、不可选中、点了不响应。

**气泡里最后看到的措辞，就是落字后的措辞。** 大润色只改标点、连接词和断句，不换词。

落字完成后气泡消失，不留残影。

### 4. 两级润色

**小润色（句级 · 实时 · 可见）**
句子一闭合就改：去口头语、补标点、修同音错字、口语词换书面词。
不改语序、不合并或拆分句子、不动数字与专有名词。

**大润色（段级 · 落字前 · 不可见）**
整段再通顺一遍，统一语气和标点，调整断句与连接。
只允许动标点、虚词、语序、断句；**实词集合必须与气泡最后一帧完全一致**。

**分工：小的管措辞，你能看见；大的管通顺，你看不见，但也不许换词。**

**深度档（可选，默认关闭）**
标准档之上再加一档：允许同义改写，允许把步骤/并列/条件整理成清单（`1. 2. 3.`）。
代价是松手后多等 1–2 秒（气泡显示「深度整理中」），所以按需切、不默认开。
深度档放宽的是**改写幅度**，不是**事实**：数字、人称、否定、条件、时态仍然不许动。
这些事实项目前只做记录不拦截（先积累真实语料再定阈值），记录进开发日志。

> **2026-11-02 修订（口语长文优先）**
> 标准档不再只是「删语气词 + 补标点」：它要**合并被停顿切碎的短句、按语义分段**，
> 仍然只动标点、虚词、语序、断句，不动实词。
> 长口述不再守 800ms，上限放到 8 秒。
> **本地模型只有一套提示词**（2 条规则；编号清单由规则层按标记确定性排版）；
> 深度档只在接云端 API 时开放 —— 2B 吃不下长提示，会把整段话包成「1.」。
> 800ms 仍是增量润色上线后的目标（见第四节末）。

两档共用一条硬规则：**模型爱写的 markdown 记号一律被程序改写成规整编号**，
落进输入框的永远是干净文本，不是 `-` `*` `#`。

### 5. 长口述自动分段

说话过程中有较长停顿，就把前一段提前处理、提前落字。说十分钟，也是每段等一两秒，而不是最后等二十秒。

**段边界条件**（三者同时满足才切段）：

- 静音 ≥ 700ms
- 该段 ≥ 15 字 或 ≥ 4 秒
- ASR 已给出句末标点

落字段的边界就是大润色的边界。**已落字段落不再回溯修改。**

### 6. 鼠标旁的状态指示

鼠标边上一个极小的圆点，始终跟着，不挡操作。**没说话时完全静止。**

状态集合：静止 / 聆听（随音量起伏）/ 处理（显示进度）/ 已落字（短暂确认）/ 出错（短暂）。

作用只有一个：让你随时知道它开着、它在听、它听对了。

### 7. 词典与热词

可手动维护一份词表：人名、公司名、产品名、专业术语、缩写。支持导入导出。

热词两重作用：识别时优先命中；润色时**不改写、不翻译**。

### 8. 模型可替换

给用户的不是一堆模型名，而是可解释的几档取向：**更快 / 更准 / 更强**。
控制面板「模型」页可以直接切换，不需要改配置文件或重启：

- **本地语音模型**：SenseVoice Small（默认，低延迟）/ Qwen3-ASR 0.6B（更准，约 1 秒/句）；
  切换时重新加载模型，正在录音会先结束当前一轮。
- **润色模型 / API**：保存多套配置，本地 Ollama 与 OpenAI 兼容 API 都能用；
  每套配置可测试连接、编辑、删除，点「使用」立即生效。
- **高级用户**：配置文件 `models/asr.json`、`models/polish.json` 可手工编辑；
  当前润色配置同步写入 `models/llm.json`，兼容旧版本。
- ASR 本地推理，音频不出本机；只有云端润色才会把当前段落发出去。

切模型立即生效，不影响已有历史。音质/术语取舍见
[bench/ASR-COMPARISON.md](../bench/ASR-COMPARISON.md)。

### 9. 输入历史

每次落字留一条：最终落字文本、时间、目标应用、润色档位。

可回看、可复制、可删除、可一键清空。默认保留 30 天，可配置。

"刚才那句没落好，从历史里再拿一次"：重新落点到当前光标；当前没有可用输入框时，复制到剪贴板。

只存本机，不参与任何同步。

### 10. 全局可用与降级

凡是能打字的地方都能用：浏览器、微信、Word、IDE、终端、AI 对话窗口。不针对具体应用做特殊适配，保持行为一致。

**明确排除**：密码框（永不落字）、提权（管理员）窗口。

**降级链**（逐级尝试）：

1. 原地写回
2. 剪贴板 + 圆点提示
3. 只进历史，不打扰

触发降级的条件：锚点失效（控件销毁 / 焦点离开 / 用户已在该输入框输入）、目标拒绝写入、写入后读回校验失败。

## 四、时序与延迟预算

一次口述的状态机：

```
按住键   → 气泡出现
说话中   → ASR 流式出字；句子闭合后小润色，气泡内原地替换
较长停顿 → 该段大润色 → 落字 → 气泡清空，继续
松手     → 最后一段大润色 → 落字 → 气泡消失
```

**关键路径**只有一段：`最后一个字 → ASR finalize → 大润色 → 写入`。小润色完全在气泡里，不上关键路径。

**增量大润色**：每句闭合、小润色出结果后，后台立刻对"该句 + 上文"跑一次大润色并缓存。松手时只需处理最后一句。

| 环节 | P50 | P95 |
|---|---|---|
| 松手 → ASR finalize | 100ms | 150ms |
| 最后一句增量大润色 | 200ms | 400ms |
| 写入 + 焦点校验 | 50ms | 100ms |
| **松手 → 文字出现** | **350ms** | **650ms** |

目标：**P95 ≤ 800ms**。若去掉增量、整段重跑大润色，100 字会到 1.5–2.5s，直接击穿目标——所以增量大润色是达成指标的必要条件，不是优化项。

另一条硬指标：**句末到气泡更新 ≤ 300ms**，否则气泡会落后于说话。

## 五、保真契约

两级润色的边界不是"感觉差不多"，是可以自动检验的规则。

**小润色允许**：删口头语（嗯、那个、就是说）、补标点、修同音错字、口语词换书面词（"整一下"→"处理一下"）。

**小润色禁止**：改语序、合并或拆分句子、动数字、动专有名词、动英文术语。

**大润色允许**：增删标点、增删连接词（"然后""所以"）、调整断句位置、调整语序。

**大润色禁止**：替换任何实词、增删任何信息、改变否定/条件/时态。

**检验方法**：对"气泡最后一帧"和"落字结果"做 diff，抽取实词集合，必须完全相同。不一致即视为 bug。

**失败处理**：大润色超时或校验不通过，回退到小润色结果落字，圆点短暂提示，不阻塞。

## 六、落点与降级

**锚点**：按下说话键瞬间，记录目标输入框（窗口 + 控件 + 插入点）。

**落点冲突规则**：落字前校验锚点。若用户已经在别处输入、焦点已离开、或控件已销毁，**放弃自动落字**，转入降级链。宁可让用户从历史里再拿一次，也不把字插到错的地方。

**写入方式**：一次性写入，输入框里只出现定稿。剪贴板中转，写入前后保存与恢复用户剪贴板。

三条必须遵守的写入约束：

- **修饰键守卫**：注入前确认 Shift / Ctrl / Alt / Win 全部抬起，最多等 500ms。按住说话的热键（尤其改键成 Alt 类）在松手瞬间可能仍处于按下状态，此时注入会变成组合键。超时则放弃本次写入、转入降级——宁可这次不落字，也不打出乱码。

- **剪贴板条件恢复**：只有"当前剪贴板内容仍等于我们刚写进去的文字"时才恢复原内容。用户在这几百毫秒里自己复制了东西，就以用户的为准，不覆盖。
- **连续写入合并**：分段落字会连续写多次。恢复动作按批次合并，整次口述只还原最早那一份原剪贴板。

**写入结果**：每次写入返回四态之一，并携带实际写入的字符数。

| 状态 | 含义 | 后续 |
|---|---|---|
| 已插入 | 全部写入成功 | 完成 |
| 部分插入 | 只写进了一部分 | 保留已写入部分，提示用户检查 |
| 已复制降级 | 没写进去，但内容已在剪贴板 | 圆点提示，不打扰 |
| 失败 | 写入与剪贴板均不可用 | 只进历史 |

**焦点丢失即复制**：落字前发现锚点已经失去焦点，不再尝试把字插到别处，
直接写进剪贴板并提示「已复制到剪贴板，按 Ctrl+V 粘贴」。不依赖目标应用的 Ctrl+Z，
也不做「先插进去再回删」这类有副作用的补偿。

**实验开关**：流式逐字写入（边说边出现、松手后局部回删重打）只作为默认关闭的实验项，用于验证需求强度，不进主线。

## 七、隐私与数据

- **音频永不出本机**：ASR 本地流式，麦克风数据不落盘、不上传
- **文本仅在云端大润色时出网**：只发当前段落，不带历史、不带应用名、不带窗口标题
- **历史仅存本地**：不参与同步、不上报
- **一键清空即真删**：包括本地日志，不做"软删除保留 30 天"
- **密码框永不落字**：识别到密码类控件直接拒绝
- 云端大润色的供应商与数据保留承诺，需在首次使用前明示

## 八、怎么算成功

**北极星指标：落字后人工改写率** —— 落字之后，用户在 5 分钟内又手动改动了多少字。

计量单位是**语义单位**，不是字符：中文一个字、英文一个单词、一串数字各计 1。否则 `Kubernetes` 会被算成 10 个字符，中英混说场景下的指标严重失真。

它同时度量两件事：整理得好不好、内容有没有走样。首版目标 ≤ 10%（初值，跑两周真实数据后校准）。

| 指标 | 目标 |
|---|---|
| 落字后人工改写率 | ≤ 10%（初值） |
| 松手 → 文字出现 | P95 ≤ 800ms |
| 句末 → 气泡更新 | ≤ 300ms |
| 首次落字成功率 | ≥ 99% |
| 气泡 → 落字措辞一致率 | 100%（硬指标，违反即 bug） |

## 九、形态与阶段

- **当前形态**：本地桌面应用（Windows 优先，跨平台）
- **未来形态**：作为 DeepSeek 生态下的插件存在，能力不变、外壳不同

产品内核只做一件事：**一段音频进去，一段成品文字出来。**

桌面应用和插件都是它的外壳，换壳不改内核。内核与外壳之间只依赖一个契约：音频进、文字出、落点由外壳提供。

## 十、ASR 选型

**一个运行时**：sherpa-onnx（Apache-2.0，Rust crate 2.x），不引入第二个推理引擎。

| 用途 | 模型 | 形态 |
|---|---|---|
| 气泡灰字 | streaming zipformer bilingual zh-en | 真流式，约 320ms 一跳 |
| 定稿 | SenseVoice int8（zh / en / ja / ko / yue） | 离线，一句一跑 |
| 段内切句 | silero VAD | 运行时内置 |
| 热词纠错 | 拼音 / 编辑距离后处理 | 模型之外 |

**为什么**：SenseVoice 把中英混说当主场景、输出自带标点与 ITN、自带同音字替换器；sherpa-onnx 的 Rust 绑定是一等公民，官方带 Tauri 示例。

**与保真契约的配合**：灰字可错（允许被替换），实字锁定（句子闭合后重识别 + 小润色，此后不再变）。双引擎不破坏"措辞即落定"，因为用户看到并记住的是实字。

**不选**：FunASR Python 运行时（部署重、依赖 torch）、CapsWriter 的 GGUF 路线（单人项目 + 自研 GGUF 导出，锁死 llama.cpp）、whisper.cpp（中文标点弱、非真流式）。Qwen3-ASR 留作"更强"档的升级路径，不进 v1。

**降级路径**：低端机关掉 zipformer，只用 VAD + SenseVoice 伪流式，灰字变成约 500ms 一跳，功能不残。

### 首个 spike 的验收标准

**素材**：20 段真实的中英混说技术口述，每段 10–30 秒，每段至少 5 个英文术语或产品名，覆盖写注释、写邮件、写 issue 三类场景。

| 指标 | 门槛 | 测法 |
|---|---|---|
| 定稿字错率（中文字 / 英文词） | ≤ 8% | 人工标注参照，按字与词分别统计 |
| 英文术语保留率 | ≥ 90% | 术语未被音译成中文 |
| 单句识别延迟 | P95 ≤ 250ms | CPU int8，5–10 秒音频 |
| 首个灰字出现 | ≤ 500ms | 从张嘴到气泡出字 |
| 常驻内存 | ≤ 800MB | 两个模型 + 运行时 |
| 冷启动到可说话 | ≤ 3s | 双击图标开始计时 |
| 热词纠正成功率 | ≥ 80% | 50 词表，注入 20 个专有名词 |
| 热词误替换率 | ≤ 2% | 非目标词被误改的比例 |

**判定**：任一项不过，按对应路径降级——准确率不过换更强档；延迟不过关灰字；内存不过缩模型或转纯离线路线。

**产出**：`bench/` 下一张结果表 + 素材集（音频不入库）。

## 十一、待定

1. 默认键位——需避开输入法中英切换（Ctrl+Space）与系统快捷键（Win+Space）
2. 本地强模型的最低硬件门槛（显存/内存）及不达标时的降级路径
3. 历史默认保留 30 天是否合适（隐私与"再拿一次"的取衡）
4. 云端大润色的供应商与数据保留承诺
5. 是否承诺英文为主的口述（当前只承诺中英混说）
6. 插件形态下"落点"的定义（没有输入框时落在哪）

## 附：关键决策记录

| 决定 | 结论 | 理由 |
|---|---|---|
| 目标用户 | 中英混说的技术/办公人群 | 术语多、混说刚需，最吃"落点不丢"和"术语不改写" |

| 落字方式 | 一次性写入，只出现定稿 | 让草稿进入正式文档，等于自毁"不是逐字转写"的定位 |
| 流式写入 | 默认关闭的实验开关 | 技术可行但产品上不利；保留验证需求强度的通道 |
| 延迟目标 | 短句 P95 ≤ 1.5s；300 字以内 3–5s；超过 300 字 ≤8s（增量润色未上线前的折中） | 长口述的「整理」比 800ms 更值钱，用户已确认可以等 |
| 达成手段 | 增量大润色（未实现）/ 现阶段按字数分档 + 硬超时回退 | 整段重跑 100 字需 1.5–2.5s，必然击穿 800ms |
| 大润色时序 | 落字前完成，不可见 | 兑现"输入框只出现定稿" |
| 大润色档位 | 标准档默认，超过 300 字自动切深度档 | 标准档合并碎句/分段且能 diff 校验；深度档用 1–2 秒换改写与分点 |
| 小润色时机 | 句子闭合就进气泡 | 让用户看到的就是成品，落字不再是"突然变干净" |
| 显示即落定 | 改写为"措辞即落定"（实词集合不变） | 原承诺在时序上不成立，改成可 diff 检验的规则 |
| 整段原地替换 | 不做 | Windows 上通用范围编辑只有 TSF＝变成输入法，与用户现有输入法互斥 |
| ASR 运行时 | sherpa-onnx 单运行时 | Rust 一等绑定、官方 Tauri 示例、一个库同时支持流式与离线 |
| ASR 模型组合 | 流式 zipformer 出灰字 + SenseVoice 定稿 | 灰字要低延迟，定稿要准确率，职责分离 |
| 修饰键守卫 500ms | 实测通过，保留 | 200ms 的真实松键延迟被正确等到（223ms 放行），500ms 仍按住时放弃且零写入 |
| VAD 断句 | 默认关闭 | 实测负收益：切碎后丢上下文，CER 7.5%→8.2~14.9%，术语 81%→56~70%，延迟没变好 |
| 默认定稿模型 | SenseVoice int8（速度优先） | 8 项门槛过 7 项；换 Qwen3-ASR 术语可到 96% 但识别 146ms→1131ms，击穿延迟承诺 |
| 识别语言参数 | 固定 zh，不用 auto | 短音频上 auto 会误判成日/韩语，混合语料 CER 7.5%→6.2%；纯英文场景代价 10 个百分点 |
