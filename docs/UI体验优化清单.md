## 0. 怎么用这份清单

- **ID 规则**：`UX-1xx` 控制面板，`UX-2xx` 托盘，`UX-3xx` 动效。编号分配后不复用。
- **优先级**：`P0` 不修就会让用户怀疑「它坏了 / 没生效」；`P1` 明显缺口，排进本轮；`P2` 打磨，随版本带走。
- **工作量**：`S` ≤ 0.5 天，`M` 1–2 天，`L` 3–5 天（含自测，不含真人回归）。
- **验收**：全部写成可观察的现象（录屏、盲测、指标、脚本），不写「体验更好」。
- **推进方式**：一条改动只碰一个维度，便于回滚；跨维度的依赖写在条目标题下。

## 1. 现状基线

| 界面 | 形态 | 技术 | 主要文件 |
|---|---|---|---|
| 控制面板 | 760×620，居中，系统标题栏，4 个页签（概览/历史/词表/设置） | WebView2 + 原生 invoke | `app/src/settings.html` `settings.css` `settings.js` |
| 底部气泡 | 440×100，屏幕下方居中，透明置顶、鼠标穿透 | 独立透明窗口 + 事件推送 | `app/src/bubble.*`、`src-tauri/src/bubble.rs` |
| 光标指示器 | 72×72，跟随鼠标 +18/+20，30Hz 挪窗口 | 独立透明窗口 + 60ms 电平事件 | `app/src/indicator.*`、`src-tauri/src/bubble.rs` |
| 系统托盘 | 原生菜单，四态图标，左键开面板、右键菜单 | Tauri `TrayIconBuilder` | `src-tauri/src/tray.rs` |

三个关键约束，后面所有建议都不能突破：

1. **落字是唯一关键路径**：松手 → 文字出现 P95 416ms，任何动效都不能加等待。
2. **句末 → 气泡更新 ≤ 300ms**（产品定义硬指标），动效只能做「已到达内容」的呈现，不能拖慢内容到达。
3. **气泡只读**（产品定义 §3）：不加点击、不加悬浮按钮，所有操作放托盘或面板。

一句话判断：**功能链路已经跑通，界面层还停在「能用的原型」——所有状态靠用户自己记，所有变化都是瞬时的。**

## 2. 三个维度的结论

- **控制面板**：信息按「控件类型」而不是「用户任务」组织。5 个页签里 3 个是开关/参数、1 个是数据、1 个是调试台；用户打开面板最常见的两个诉求——「刚才为什么没落字」和「改个词」——都要先找页签。
- **托盘**：它现在只是一个**菜单入口**，不是一个**状态显示器**。图标恒定、左键无响应、开关两处不同步、失败只闪 1.2 秒气泡。
- **动效**：目前几乎没有过渡，窗口和文字都是硬切。该补的不是装饰，而是「出现 / 定稿 / 等待 / 结果」四类反馈，并且必须服从 416ms 预算。

**只做六件事的话**：`UX-106` 面板关了就打不开 → `UX-204` 开关两处不同步 → `UX-102` 概览给出就绪状态 → `UX-201`+`UX-206` 托盘三态与暂停反馈 → `UX-302` 气泡进出场与落点 → `UX-301` 动效令牌（后面所有动效的地基）。

## 3. 维度 A：控制面板（信息架构与布局）

### 3.0 目标信息架构

```
言出
├─ 概览      现在能不能用 · 刚才那句去哪了 · 快捷键
├─ 历史      按天 / 可搜 / 可复制 / 可删（带确认）
├─ 词表      热词 + 替换规则（表格 / 源码双模式）
└─ 设置      外观（气泡）· 引擎与模型 · 试润色（折叠）· 数据与重置
```

| 现有页签 | 去向 | 理由 |
|---|---|---|
| 状态 | 概览 | 开关和「就绪状态」是同一件事的两面，应该同屏 |
| 历史 | 历史（保留） | 唯一的「产出」视图，独立成区 |
| 热词 | 词表 | 热词和替换规则是同一类对象，继续同页 |
| 润色 | 设置 › 高级 · 试润色 | 这是调试工具，不是日常设置 |
| 气泡 | 设置 › 外观 | 外观参数与引擎、数据同属「配置」 |

三条原则：**一级页签按用户任务分，不按控件类型分**；**同一状态只在一个地方可改**；**调试能力保留，但不占一级入口**。

### UX-101 一级导航：按「对象」重排，而不是按「控件」

`P1 · M · 依赖 UX-105`

- **问题现状** `settings.html:15-21` 五个页签并列：「状态」里是三个开关，「气泡」是参数，「润色」是调试台，「热词」是数据编辑，「历史」是只读列表——四类对象混在同一层。页签与面板的对应关系硬编码在 `settings.js:13-15`，加一个页签要同时改 HTML、JS 和 `invoke` 分发。
- **优化方案** 收敛为 4 个一级页签（见 3.0）；「试润色」降为设置页里的折叠区（默认收起，标题「高级：试一段」）；页签加 16px 图标 + `1–4` 快捷键；用 `location.hash` 记住上次页签，下次打开直接回到原处。
- **预期收益** 一级入口 5→4，设置类内容集中；用户第二次打开不用重新找；后续加「关于」「快捷键」不再挤页签。
- **验收标准** 新 IA 下完成「查昨天一条记录并复制」≤ 2 次点击；关闭再打开面板停留在上次页签。

### UX-102 概览：先回答「现在能不能用」

`P0 · M · 依赖 UX-101`

- **问题现状** 状态页只有 3 个开关 + 3 行只读元信息（`settings.html:25-46`）。而三件最会静默失败的事都没上界面：麦克风打开失败只写日志（`lib.rs:251-257`）、热键注册失败直接向上抛（`lib.rs:259-277`）、模型预热在后台线程里（`lib.rs:299-314`）。`tools/panel-shot.png` 里下半屏整片空白，正好是这块该放的东西没放。
- **优化方案** 顶部「就绪」卡，4 行状态：

  | 行 | 内容 | 失败时 |
  |---|---|---|
  | 麦克风 | 设备名 + 实时电平条（复用 60ms 电平） | 红点 + 原因 + 「重试」 |
  | 识别模型 | 未加载 / 预热中 / 就绪 + 引擎名 | 红点 + 「查看日志」 |
  | 触发键 | 右 Alt 已注册 / 被占用 | 琥珀点 + 「如何排查」 |
  | 润色 | 标准 / 深度 / 不可用（未配置 API） | 灰点 + 「去配置」 |

  状态点 8px + 12px 文案；色值 `#059669` / `#2563eb` / `#d97706` / `#dc2626`。卡片下方放「最近一次落字」：时间、目标应用、字数、耗时、复制按钮。
- **预期收益** 把「说了没反应」从猜变成看；麦克风、热键这两类静默失败第一次有出口；面板下半屏不再空。
- **验收标准** 占用/拔掉麦克风后打开面板，5 秒内显示红色状态与重试按钮；点重试后回到就绪；最近一条落字可见且可复制。

### UX-103 历史：从「日志列表」变成「能找回东西」

`P1 · M · 需后端补字段`

- **问题现状** 每条固定三行 diff（`settings.js:91-112`），没有目标应用（`history.rs` 的 `Entry` 只有 raw/corrected/ruled/final/used_llm/depth/ms，没有 target）、没有复制、没有搜索。「清空这一天」单击直接删除（`settings.js:182-185`）。整天记录一次性渲染，每条都跑一遍 O(n·m) LCS（`settings.js:122-153`），几十条长文本足以卡住主线程。
- **优化方案**
  1. **列表行化**：时间 · 首行摘要（单行省略）· 目标应用图标 · 字数 · 档位徽章；hover 浮出「复制」「展开」。
  2. **展开才渲染 diff**，单条 > 800 字改「查看对比」按需计算，结果缓存；后端在 `Entry` 增加 `target` 字段（落字时 `anchor` 已抓到窗口标题，devlog 也记了同样的东西）。
  3. 顶部：搜索框（本地过滤）+ 档位筛选 + 「仅看大润色」。
  4. 删除改为两步：按钮变红 → 二次确认；或删除后 5 秒内「撤销」。
  5. 「保留 30 天」做成可配（产品定义 §9），入口放这里。
- **预期收益** 目标用户最常做的是「找回刚才那段」，现在能在 2 次操作内完成；误删整天的风险归零；长历史不再卡。
- **验收标准** 200 条/天数据首屏 < 300ms 可交互；搜索 3 字内出结果 < 100ms；删除必须两步；复制后有 toast。

### UX-104 词表：把「裸文本框」升级成可校验的编辑器

`P1 · L`

- **问题现状** 两个 textarea 直接编辑磁盘文件（`settings.html:69`、`76`），没有行号、没有校验、没有重复检测；说明全靠 placeholder；保存后只改一行 hint（`settings.js:194-205`）。截图里 163 条词表（`panel-shot.png`），靠肉眼定位一行几乎不可行；切页或关窗不提示未保存。

## 5. 维度 C：动画效果（过渡 / 反馈 / 加载）

### 5.0 动效原则（先定规矩，再谈效果）

动效只服务四件事：**出现**（我从哪来）、**定稿**（这句不会再变）、**等待**（还在处理、大概多久）、**结果**（成了 / 失败了）。

四条硬约束：

1. 不阻塞输入，不改变文字到达的时间（文字该多快还多快，动效只做「到达后」的呈现）。
2. 单次 ≤ 240ms；只动 `transform` / `opacity`；不触发重排。
3. 尊重 `prefers-reduced-motion`，关位移、留淡入。
4. 不做：逐字打字机（和流式识别打架，让「说完了」显得更慢）、全屏庆祝、模糊/粒子背景。

### UX-301 动效令牌与降级开关

`P1 · S · 所有动效的前置`

- **问题现状** 时长散落在 70 / 90 / 160 / 200 / 900 / 1200 / 1400 / 1800ms（`indicator.css:48,57,65,90,82`、`settings.css:94,99`、`bubble.css:76,90`）；缓动只有 `ease` / `ease-out` / `linear`；全仓没有 `prefers-reduced-motion`。
- **优化方案** 在共用 `tokens.css` 定义：

  ```css
  --dur-instant: 80ms;   /* 按压、hover */
  --dur-fast:    160ms;  /* 控件、颜色、状态切换 */
  --dur-base:    220ms;  /* 浮层进出、页签 */
  --dur-slow:    320ms;  /* 一次性确认动画 */
  --ease-out:    cubic-bezier(.2, .8, .2, 1);
  --ease-in-out: cubic-bezier(.4, 0, .2, 1);
  --ease-spring: cubic-bezier(.34, 1.56, .64, 1); /* 只给小元素，别用在浮层 */
  ```

  再加快捷降级：`@media (prefers-reduced-motion: reduce)` 与 `YANCHU_REDUCED_MOTION=1` 走同一套规则——关循环动画与位移，只留 ≤ 80ms 的淡入。
- **预期收益** 后续所有动效不再拍脑袋定 70/160/900；无障碍合规；降级只需改一处。
- **验收标准** `grep -E '[0-9]+ms' src/*.css` 只命中令牌定义；reduced-motion 下无循环动画（呼吸、旋转全停）。

### UX-302 气泡的进出场与落点

`P1 · M`

- **问题现状** `win.show()` / `win.hide()` 是瞬时的（`bubble.rs:112-120`、`175-182`），落字后 1100ms 直接消失（`lib.rs:988`）。位置固定屏幕底部居中，与产品定义「光标附近」不一致，但 2026-11-03 已决定**保持底部居中**。
- **优化方案**
  1. **出现**：220ms 淡入 + `scale(.97)→1` + `translateY(6px)→0`；**消失**：120ms 淡出 + `translateY(4px)`。由 Rust 的 `shown` / `hiding` 事件加类触发，窗口尺寸不变。
  2. **定稿**：`done` 时 320ms 绿色描边脉冲（::after，不影响文字），再停 900ms 淡出；总时长不变。
  3. **落点**：保持屏幕下方居中；本轮不做跟随插入符。
- **预期收益** 从「闪一下」变成「有来有去」；定稿有明确确认感，且不增加等待。
- **验收标准** 120fps 录屏里出现/消失各 ≥ 2 帧过渡；快速连续触发不会把新一轮气泡关掉；落字 P95 ≤ 800ms（含 140ms 退场）。

### UX-303 指示器四态可辨

`P1 · S`

- **问题现状** 状态靠颜色 + spinner（`indicator.css:79-101`）；`listening` 态**没有对应样式**（`start_session` 发的是 `listening`，`bubble.rs:123`），首帧会闪一下默认样式；切换时 spinner 瞬间出现、ring 透明度跳变；`done` 只变绿，没有「完成」的形。
- **优化方案**
  - 所有状态切换统一 160ms 交叉淡化；spinner 用 `opacity + scale(.92→1)` 进入，不用硬切。
  - `done`：环收拢（scale 1→.82）→ 中心画勾（`stroke-dashoffset` 220ms）→ 保持 500ms，替代单纯变绿。
  - `notice`：1 次 2px 横向抖动（120ms）+ 琥珀色，不循环。
  - `polishing`：环上一段 90° 弧做 1.2s indeterminate，替代整圈 900ms 匀速（匀速整圈看起来像卡住）。
  - 补 `[data-state="listening"]` 规则：环常亮、core 不呼吸，与 `silent` 区分。
- **预期收益** 「在听 / 在想 / 成了 / 错了」四态可辨，对应产品定义 §6 的状态集合。
- **验收标准** 5 人看截图盲测识别率 ≥ 90%；无首帧闪烁。

### UX-304 文字定稿的反馈

`P1 · M`

- **问题现状** 每 450ms 整段替换 `textContent`（`bubble.js:29-54`；`lib.rs:659`、`711`）；已定稿和草稿只靠颜色深浅区分（`bubble.css:65-66`）；句子定稿那一刻没有任何反馈；顶部溢出只有 mask（`bubble.css:60-63`），没有滚动过渡。
- **优化方案**
  - 新定稿的句子：120ms 背景高亮从 `rgba(37,99,235,.10)` 淡到 0，只做一次。
    **2026-11-05 已改为纯颜色过渡（灰 → 正文色 160ms，不闪背景），见 0.4**。
  - 草稿尾巴：200ms 颜色过渡；**不加闪烁光标**（2026-11-03 用户反馈去掉）。
  - 溢出：内容增高时用 `translateY` 120ms 缓动，替代无过渡裁切。
  - **不做逐字动画**：流式识别本来就在改字，再加打字机会把「说完了」的体感拖慢。
- **预期收益** 强化「定稿 = 可信」，降低文字抖动带来的「它在乱改」错觉。
- **验收标准** 连续说 30 秒，气泡无整段闪烁；定稿高亮每次只出现一次；没有常驻闪烁元素。

### UX-305 等待与加载

`P1 · M`

- **问题现状** 标准档等待只有文字呼吸（`bubble.css:74-77`），深度档多一行字（`bubble.css:80-91`），没有已用时长；模型预热、历史加载、试润色都没有 loading 态，按钮可重复点（`settings.js:235-237`）。
- **优化方案**
  - 延迟 600ms 才显示进度（避免快请求闪一下）：气泡状态行「整理中 · 1.2s」+ 2px indeterminate 进度条；超过 5s 改文案「还在处理，可以先继续说话」。
  - 历史：3 条骨架屏（高度与条目一致），加载完成 120ms 淡入。
  - 试润色：按钮内联 spinner，期间禁用其余两个按钮。
  - 模型预热：概览显示「模型预热中…」，完成变「就绪」并 160ms 高亮。
- **预期收益** 等待体感下降；不重复提交；知道系统没死。
- **验收标准** 2 秒等待场景下用户不重复按键（5 人测试）；骨架屏与真实条目高度差 ≤ 4px，无跳动。

### UX-306 控件反馈：按下、成功、失败、禁用

`P1 · S`

- **问题现状** 按钮只有 hover（`settings.css:127`），没有 `:active` / `:focus-visible` / `:disabled`；保存成功只改一行 hint（`settings.js:197`）；「清空这一天」和普通按钮同权重（`settings.css:132`）。
- **优化方案** hover 80ms 底色；active 60ms `scale(.98)`；focus-visible 2px 环；成功：按钮 160ms 变绿 + 勾，2s 后恢复，同时角落 toast（2s）；危险操作红色描边 + 二次确认；禁用 40% 透明；可点区域 ≥ 32px 高。
- **预期收益** 操作确定性；误删风险下降。
- **验收标准** 每个保存/删除都有 ≤ 200ms 的可见反馈；键盘焦点始终可见。

### UX-307 页签与面板切换

`P2 · S`

- **问题现状** `.pane` 用 `display:none` 硬切（`settings.css:63-64`），页签 active 只有静态底色；面板打开无过渡。
- **优化方案** 内容 120ms 淡入 + 4px 上移（不做出场）；页签指示器用共享滑块（180ms，`transform` 驱动）；面板首次显示 160ms 淡入。总时长 ≤ 200ms，reduced-motion 下只留 opacity。
- **预期收益** 空间连续感，不牺牲效率。
- **验收标准** 切换页签 ≤ 150ms 完成且无布局跳动；快速连点 5 次不堆积动画。

### UX-308 指示器跟随的平滑

`P2 · M`

- **问题现状** 30Hz `set_position` 硬挪窗口（`bubble.rs:66-80`），快速移动会「跳格」；音量只有 70ms 过渡（`indicator.css:48,57`），静音回落时突然缩回；电平 16Hz（`lib.rs:509`）。
- **优化方案** 光标位置一阶低通（lerp 0.35，60Hz）或至少 60Hz 更新；音量包络 attack 40ms / release 180ms（上升快、回落慢）；窗口位置 100ms 一次，页内做 ≤ 8px 偏移补偿，减少窗口移动。
- **预期收益** 跟手但不抖；更少窗口重排。
- **验收标准** 快速画圈时指示器不脱离光标 > 40px；静音回落无突跳。

### UX-309 动效性能预算与降级

`P1 · S`

- **问题现状** 气泡/指示器是透明 WebView2 独立窗口 + `alwaysOnTop`；动画一旦触发重排就掉帧；没有 FPS 观测；`bubble` 的 `max-height`、mask 变化都可能引起重排。
- **优化方案** 只动 `transform` / `opacity`；`will-change` 用完移除；预算 60fps，连续 3 帧 > 20ms 自动关非必要动效并记日志；提供 `YANCHU_REDUCED_MOTION=1` 手动降级；用 DevTools Performance 录 10s 作为验收证据。
- **预期收益** 低端机不卡；不动落字关键路径（P95 416ms）。
- **验收标准** 录音 30s 掉帧 < 1%；落字 P95 不回退（仍 ≤ 800ms）。

## 7. 验收方法

| 类型 | 做法 | 看什么 |
|---|---|---|
| 浮层动效 | Windows 录屏 120fps，逐帧看 | 出现/消失是否 ≥ 2 帧过渡，是否有白闪 |
| 性能 | DevTools Performance 录 10s | dropped frames、Layout 次数、长任务 |
| 状态一致性 | 脚本连续切换 20 次（可扩成 e2e） | 两端 ≤ 200ms 一致，无漂移 |
| 可辨识 | 5 人看截图盲测 | 三态/四态识别率 |
| 首次使用 | 5 名新用户，不给引导 | 到第一句落字的时间 |
| 等待体感 | 人为注入 2s 延迟 | 是否重复按键、是否误判卡死 |
| 回归 | `tools/e2e-test.ps1` + `devlog` | 落字 P95 不回退，插入失败率不变 |

## 8. 不做清单

- **气泡逐字打字机**：和流式识别抢同一块文字，且让「说完了」看起来更慢。
- **全屏庆祝 / 粒子 / 模糊背景**：低端机成本高，和工具定位不符。
- **超过 240ms 的页面转场**：面板是效率工具，不是展示页。
- **气泡内可点击操作**：产品定义明确只读、点了不响应；操作统一放托盘或面板。
- **自绘标题栏**：现在系统标题栏够用，自绘会引入拖拽、高 DPI、无障碍成本。
- **常驻悬浮历史窗**：遮挡输入区，和「不挡操作」冲突。

## 9. 待产品确认

1. **触发键**：右 Alt 固定不可改；CapsLock 是已知边界（README「已知边界」）。要不要在概览里提供「更换触发键」？
2. **深度档开放范围**：现实现只对云端 API 开放（`llm.rs:156-160`），面板文案要与此一致。
3. **历史保留**：30 天是否做成可配，还是固定值。
4. **托盘左键语义**：已按建议定为「打开面板」，中键暂停留待 UX-203 一起做。
5. **托盘「复制最近一次落字」**：会写用户剪贴板，需要明确隐私口径后再加。
